# Introduction to Logs

Attackers often try to **hide their activities** to avoid being detected.

However, every action performed on a system usually leaves behind **digital traces**.

These traces are called **logs**.

Security teams analyze these logs to understand:

* What happened?
* When did it happen?
* Who performed the action?
* How did the attack occur?

Logs are one of the most important sources of evidence during incident investigations.


# What is a Log?

A **Log** is a record of an event that occurred on a system, application, or network device.

Logs act as the **digital footprints** of user and system activities.

Both normal and malicious activities generate logs.


# Examples of Logged Events

* User login
* User logout
* File creation
* File deletion
* Software installation
* Failed login attempt
* Website access
* System error


# Why Are Logs Important?

Logs help investigators reconstruct an attack by providing evidence of system activities.

Without logs, it would be difficult to determine:

* How an attacker entered.
* What actions they performed.
* Which systems were affected.
* When the attack occurred.


# Use Cases of Logs

## 1. Security Event Monitoring

Logs help security teams monitor systems for suspicious or abnormal activities.

### Example

A SIEM detects hundreds of failed login attempts within a few minutes and generates an alert for a possible brute-force attack.

## 2. Incident Investigation and Forensics

Logs provide evidence that helps investigators reconstruct security incidents.

They are used to perform **Root Cause Analysis (RCA)**.

### Example

Investigators review authentication logs and discover that an attacker logged in using stolen credentials before installing malware.


## 3. Troubleshooting

Logs record system and application errors, making them useful for diagnosing technical problems.

### Example

A web server crashes.

The server logs reveal that the crash occurred because the disk storage became full.


## 4. Performance Monitoring

Logs can be used to monitor the performance and health of systems and applications.

### Example

Application logs show that response times become slow whenever CPU usage exceeds 90%.


## 5. Auditing and Compliance

Organizations use logs to maintain a record of user activities for auditing and regulatory compliance.

Logs help prove that security policies and legal requirements are being followed.

### Example

An auditor reviews access logs to verify that only authorized employees accessed confidential financial records.

# Types of Logs

A system generates **many different kinds of logs**.

Instead of storing everything in one place, logs are organized into **categories** based on the type of activity they record.

This makes investigations faster because security analysts only need to check the relevant log type.


# 1. System Logs

**Purpose:** Record events related to the operating system.

### Common Information

* System startup and shutdown
* Driver loading
* Hardware events
* System errors

### Example

A computer suddenly crashes.

The investigator checks the **System Logs** to identify the cause.


# 2. Security Logs

**Purpose:** Record security-related events.

These logs are the most important during security investigations.

### Common Information

* User logins and logouts
* Failed login attempts
* Permission changes
* User account changes
* Security policy changes
* Suspicious activities

### Example

An analyst wants to investigate multiple failed login attempts.

They check the **Security Logs**.


# 3. Application Logs

**Purpose:** Record events generated by applications.

Each application maintains its own logs.

### Common Information

* Application errors
* User activity
* Application updates
* Application configuration changes

### Example

A web browser keeps crashing.

The analyst checks the **Application Logs** to identify the error.


# 4. Audit Logs

**Purpose:** Record important user and system activities for auditing and compliance.

### Common Information

* User activities
* Data access
* System changes
* Policy enforcement

### Example

An auditor wants to know who accessed a confidential document.

They check the **Audit Logs**.


# 5. Network Logs

**Purpose:** Record network communication.

These logs help monitor and troubleshoot network activity.

### Common Information

* Incoming traffic
* Outgoing traffic
* Network connections
* Firewall activity

### Example

An analyst investigates suspicious outbound traffic.

They examine the **Network Logs**.


# 6. Access Logs

**Purpose:** Record access to resources such as websites, databases, and APIs.

### Common Information

* Website access
* Database access
* API requests
* Application access

### Example

A website administrator wants to know who visited the login page.

They review the **Web Access Logs**.


# Log Types Summary

| Log Type             | Purpose                   | Example                                   |
| -------------------- | ------------------------- | ----------------------------------------- |
| **System Logs**      | Operating system events.  | Startup, shutdown, hardware errors.       |
| **Security Logs**    | Security-related events.  | Login attempts, account changes.          |
| **Application Logs** | Application activities.   | Application errors, updates.              |
| **Audit Logs**       | User and system auditing. | Data access, policy enforcement.          |
| **Network Logs**     | Network traffic.          | Firewall logs, incoming/outgoing traffic. |
| **Access Logs**      | Resource access.          | Website, database, API access.            |


# What is Log Analysis?

**Log Analysis** is the process of examining logs to find useful information or suspicious activities.

The goal is to identify:

* Security incidents
* System errors
* Performance issues
* Unauthorized access
* Unusual behavior

Since systems generate thousands or millions of logs, manually searching every log is impractical.

Security teams use both:

* **Manual analysis** (reviewing logs directly)
* **Automated analysis** (using tools like SIEM)

# Windows Event Logs

Windows automatically records important system and user activities in **Windows Event Logs**.

These logs help administrators and security analysts:

* Monitor system health.
* Troubleshoot problems.
* Investigate security incidents.

Windows provides a built-in tool called **Event Viewer** to view and analyze these logs.


# Main Windows Log Types

## 1. Application Log

**Purpose:** Stores events generated by applications.

### Common Information

* Application errors
* Warnings
* Crashes
* Compatibility issues
* Application updates

### Example

Microsoft Word crashes while opening a file.

The error is recorded in the **Application Log**.


## 2. System Log

**Purpose:** Stores events related to the Windows operating system.

### Common Information

* System startup and shutdown
* Driver loading
* Hardware errors
* Service status
* Operating system errors

### Example

A device driver fails to load during startup.

The event is recorded in the **System Log**.

## 3. Security Log

**Purpose:** Stores security-related events.

This is the **most important log** during security investigations.

### Common Information

* Successful logins
* Failed logins
* User account creation
* Password changes
* Account deletion
* Security policy changes

### Example

A user enters the wrong password several times.

Each failed login attempt is recorded in the **Security Log**.

# Event Viewer

**Event Viewer** is the built-in Windows tool used to view and analyze Windows Event Logs.

It provides a graphical interface for:

* Viewing logs
* Searching logs
* Filtering logs
* Investigating security events


## How to Open Event Viewer

1. Click **Start**.
2. Search for **Event Viewer**.
3. Open the application.
4. Expand **Windows Logs**.
5. Select:

   * Application
   * Security
   * System


# Event Log Fields

Every Windows event contains important information.

| Field           | Description                                      |
| --------------- | ------------------------------------------------ |
| **Description** | Detailed information about the event.            |
| **Log Name**    | Name of the log (Application, System, Security). |
| **Logged**      | Date and time when the event occurred.           |
| **Event ID**    | Unique identifier for the event.                 |


# What is an Event ID?

An **Event ID** is a **unique number** assigned to a specific type of Windows event.

Instead of searching through thousands of logs, analysts can search for the required **Event ID**.

---

# Important Windows Event IDs

| Event ID | Description            |
| -------- | ---------------------- |
| **4624** | Successful user login  |
| **4625** | Failed user login      |
| **4634** | User logged off        |
| **4720** | User account created   |
| **4722** | User account enabled   |
| **4724** | Password reset attempt |
| **4725** | User account disabled  |
| **4726** | User account deleted   |

> You don't need to memorize every Event ID, but these are some of the most commonly used during investigations.


# Filtering Logs by Event ID

Instead of manually searching thousands of events, Event Viewer allows you to filter logs.

### Steps

1. Open **Event Viewer**.
2. Select the desired log (e.g., **Security**).
3. Click **Filter Current Log**.
4. Enter the required **Event ID**.
5. Click **OK**.

Only matching events will be displayed.


## Example

To find all successful logins:

* Open the **Security Log**.
* Filter using **Event ID 4624**.

The Event Viewer will display only successful login events.

# Web Server Access Logs

Every time a user interacts with a website, the web server records the request in an **Access Log**.

These logs help administrators and security analysts monitor website activity and investigate attacks.

A common location for Apache web server access logs is:

```text
/var/log/apache2/access.log
```

 

# Information Stored in an Access Log

A web access log contains important information about every request made to the server.

| Field           | Description                                                  |
| --------------- | ------------------------------------------------------------ |
| **IP Address**  | IP address of the client making the request.                 |
| **Timestamp**   | Date and time of the request.                                |
| **HTTP Method** | Request type (GET, POST, PUT, DELETE, etc.).                 |
| **URL**         | Resource requested by the client.                            |
| **Status Code** | Server response code (200, 404, 500, etc.).                  |
| **User-Agent**  | Information about the client's browser and operating system. |

 

# Example Access Log

```text
192.168.1.10 - - [06/Jun/2024:13:58:44] "GET /index.html HTTP/1.1" 200 "-" "Mozilla/5.0"
```

### Breakdown

| Field       | Value                |
| ----------- | -------------------- |
| IP Address  | 192.168.1.10         |
| Timestamp   | 06/Jun/2024 13:58:44 |
| HTTP Method | GET                  |
| URL         | /index.html          |
| Status Code | 200                  |
| User-Agent  | Mozilla/5.0          |

 

# Common HTTP Status Codes

| Status Code | Meaning                                |
| ----------- | -------------------------------------- |
| **200**     | Request successful (OK).               |
| **301**     | Resource permanently moved (Redirect). |
| **403**     | Access forbidden.                      |
| **404**     | Resource not found.                    |
| **500**     | Internal server error.                 |

 

# Manual Log Analysis Commands

Instead of reading logs manually line by line, Linux provides useful command-line tools for log analysis.

 

# 1. `cat`

**Purpose:** Display the contents of a file.

### View a Log File

```bash
cat access.log
```

### Combine Multiple Log Files

```bash
cat access1.log access2.log > combined_access.log
```

**Use Case**

* View log contents.
* Merge multiple log files into one.

 

# 2. `grep`

**Purpose:** Search for specific text or patterns inside a file.

### Search by IP Address

```bash
grep "192.168.1.1" access.log
```

### Search by Status Code

```bash
grep "404" access.log
```

### Search by HTTP Method

```bash
grep "POST" access.log
```

**Use Case**

* Find a specific IP.
* Search for error codes.
* Locate suspicious requests.

 

# 3. `less`

**Purpose:** View large log files one page at a time.

### Open a Log File

```bash
less access.log
```

### Useful Shortcuts

| Key       | Action                 |
| --------- | ---------------------- |
| **Space** | Next page              |
| **b**     | Previous page          |
| **/text** | Search for text        |
| **n**     | Next search result     |
| **N**     | Previous search result |
| **q**     | Quit                   |

 

# When to Use Each Command

| Command | Purpose                                 |
| ------- | --------------------------------------- |
| `cat`   | Display or combine log files.           |
| `grep`  | Search for specific patterns or values. |
| `less`  | Read large log files page by page.      |

 

# Log Analysis Workflow

```text
Access Log
     │
     ▼
View Logs
(cat / less)
     │
     ▼
Search Specific Data
(grep)
     │
     ▼
Analyze Requests
     │
     ▼
Identify Suspicious Activity
```

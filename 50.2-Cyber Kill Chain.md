# Cyber Kill Chain

The **Kill Chain** originally comes from a military concept.

The basic military idea is:

**Identify Target → Decide to Attack → Attack Target**

In cybersecurity, [Lockheed Martin](https://www.lockheedmartin.com/?utm_source=chatgpt.com) introduced the **Cyber Kill Chain framework** in 2011.

The Cyber Kill Chain explains the **stages an attacker may follow during a cyberattack**.

Simply remember:

> **Cyber Kill Chain = Attack lifecycle from planning to achieving the attacker's objective.**

The main idea for defenders is to **detect and stop the attacker at any stage**.

This is called **breaking the kill chain**.

## 7 Cyber Kill Chain Phases

| Phase                 | Simple Meaning                       |
| --------------------- | ------------------------------------ |
| Reconnaissance        | Research the target                  |
| Weaponization         | Prepare the malicious payload        |
| Delivery              | Send the payload                     |
| Exploitation          | Execute or exploit                   |
| Installation          | Establish persistent access          |
| Command & Control     | Remotely communicate with the victim |
| Actions on Objectives | Achieve the final goal               |

Easy flow:

> **Research → Prepare → Send → Exploit → Install → Control → Achieve Goal**


# 1. Reconnaissance

**Reconnaissance** is the research and planning phase.

The attacker gathers information about the target before performing the attack.

The attacker may collect:

* Employee information.
* Email addresses.
* Company infrastructure.
* IP addresses.
* Domain information.
* Technologies used.
* Business processes.
* Exposed systems.

Simply remember:

> **Reconnaissance = Learn about the target.**

Good reconnaissance allows attackers to create more believable and targeted attacks.

For example, if an attacker knows the name of the company's HR manager, they may create a phishing email pretending to be that person.

## OSINT

**OSINT** stands for **Open-Source Intelligence**.

OSINT means gathering information from **publicly available sources**.

Sources include:

* Search engines.
* News and online media.
* Social media.
* Forums.
* Blogs.
* Public records.
* WHOIS information.
* Public technical information.

Simple meaning:

> **OSINT = Intelligence collected from public sources.**

## Passive vs Active Reconnaissance

| Passive Recon                             | Active Recon                           |
| ----------------------------------------- | -------------------------------------- |
| No direct interaction with target systems | Direct interaction with target         |
| WHOIS lookup                              | Port scanning                          |
| Public social media review                | Banner grabbing                        |
| Public information gathering              | Probing open services                  |
| Usually harder for target to notice       | More likely to generate logs or alerts |

**Passive Recon = Observe without directly touching target systems.**

**Active Recon = Directly interact with the target.**

## Email Harvesting

**Email harvesting** means collecting email addresses.

Attackers may use collected emails for phishing attacks.

For example:

**Collect Employee Emails → Create Phishing Email → Send Malicious Message**

Common OSINT resources mentioned in the room include [theHarvester](https://github.com/laramies/theHarvester?utm_source=chatgpt.com), [Hunter](https://hunter.io/?utm_source=chatgpt.com), and [OSINT Framework](https://osintframework.com/?utm_source=chatgpt.com).


# 2. Weaponization

After reconnaissance, the attacker prepares the **weapon used in the attack**.

Simply remember:

> **Weaponization = Build or prepare the malicious payload.**

Three important words are:

**Malware:** Software designed to damage, disrupt, spy on, or gain unauthorized access to a system.

**Exploit:** Code or a method that takes advantage of a vulnerability.

**Payload:** Code that performs the intended action after execution or exploitation.

Easy example:

**Vulnerability → Exploit takes advantage of it → Payload performs malicious action**

During weaponization, an attacker may prepare:

* Malicious Office documents.
* Malicious macros or VBA scripts.
* Malware.
* Payloads.
* Malicious USB devices.
* Backdoors.
* C2 infrastructure.
* Phishing templates.

For example:

**Malicious Document + Malicious Macro = Weaponized Document**

The attacker has prepared the weapon but has **not delivered it yet**.

### Important Difference

**Weaponization = Prepare the malicious item**

**Delivery = Send the malicious item**


# 3. Delivery

**Delivery** is the stage where the attacker sends or transfers the malicious payload to the target.

Simply remember:

> **Delivery = Get the payload to the victim.**

Common delivery methods include phishing emails, malicious links, attachments, USB drops, and watering-hole attacks.

### Phishing Email

The attacker sends a malicious email containing:

* Malicious attachment.
* Malicious URL.

**Spear phishing** targets a specific person or organization.

Example:

**Recon → Find Finance Employee → Create Targeted Email → Send Malicious Attachment**

### USB Drop

The attacker leaves or distributes malicious USB devices.

For example, a USB may contain a company logo to make it appear legitimate.

The attacker hopes an employee connects it to a company computer.

### Watering Hole Attack

A **Watering Hole Attack** targets a website frequently visited by a specific group.

The attacker compromises or abuses the website to expose visitors to malicious content.

Simple flow:

**Victims Regularly Visit Website → Website Compromised → Victim Visits → Malicious Activity**

A victim may also be redirected to malicious content or tricked into downloading fake software.

# 4. Exploitation

**Exploitation** is the stage where malicious code executes or a vulnerability is successfully abused.

Simply remember:

> **Exploitation = The attack starts working on the target.**

Examples include:

* Malicious macro execution.
* Zero-day exploitation.
* Known CVE exploitation.

### Malicious Macro

A victim opens a malicious document.

The malicious code executes.

**Phishing Attachment → Victim Opens Document → Malicious Code Executes**

### Zero-Day Exploit

A **Zero-Day vulnerability** is a vulnerability for which defenders or the vendor may not yet have an effective fix available when exploitation begins.

Attackers may exploit it before organizations can patch affected systems.

### Known CVE

A **CVE** identifies a publicly disclosed cybersecurity vulnerability.

If an organization does not patch a known vulnerability, an attacker may exploit it.

**Known Vulnerability + No Patch → Attacker Exploits System**

## Signs of Exploitation

Security analysts may investigate:

* Unexpected process creation.
* Registry changes.
* New services.
* Suspicious command-line arguments.

For example:

**Word → PowerShell**

Depending on context, this process relationship can be suspicious.

# 5. Installation

After obtaining access, the attacker may want to **maintain access**.

This is called **Persistence**.

> **Persistence = Maintain access to a compromised system.**

The attacker wants to return even if:

* The connection is lost.
* The computer restarts.
* Initial access is removed.
* The original vulnerability is patched.

Common persistence methods include web shells, backdoors, Windows services, and Registry Run Keys.

## Web Shell

A web shell is a malicious server-side script that can provide remote command execution or access through a compromised web server.

Common languages include:

* PHP.
* ASP.
* ASPX.
* JSP.

## Backdoor

A **backdoor** provides hidden or unauthorized access to a system.

For example, an attacker may use a remote-access payload to maintain access in an authorized lab scenario.

## Windows Services

Attackers may create or modify Windows services for persistence.

The related [MITRE ATT&CK technique T1543.003](https://attack.mitre.org/techniques/T1543/003/?utm_source=chatgpt.com) covers Windows Service abuse.

A malicious service may be configured to execute a payload.

Attackers may also use legitimate-looking service names to hide malicious activity.

This is called **Masquerading**.

> **Masquerading = Make malicious activity look legitimate.**

## Registry Run Keys and Startup Folder

Attackers may add malicious programs to startup locations.

The basic idea is:

**User Logs In → Malicious Payload Automatically Executes**

This provides persistence.

## Timestomping

**Timestomping** means modifying file timestamps.

Timestamps may include:

* Created time.
* Modified time.
* Accessed time.

Attackers may alter timestamps to make malicious files appear older or more legitimate.

Simply remember:

> **Timestomping = Manipulate file timestamps to make investigation harder.**

# 6. Command and Control

After malware or a backdoor is active, the compromised system may communicate with attacker-controlled infrastructure.

This is called **Command and Control**, commonly written as **C2 or C&C**.

Simply remember:

> **C2 = Remote communication between an attacker and a compromised system.**

The communication may look like:

**Attacker C2 Server ↔ Compromised Computer**

The attacker may use the channel to:

* Send commands.
* Receive information.
* Manage compromised systems.
* Deliver additional payloads.

## C2 Beaconing

**Beaconing** means the infected system communicates with C2 infrastructure at repeated intervals or according to a communication pattern.

For example:

**Victim → C2**

Wait.

**Victim → C2**

Wait.

**Victim → C2**

This repeated communication is called **C2 beaconing**.

## Common C2 Channels

### HTTP and HTTPS

Attackers may abuse:

* HTTP port 80.
* HTTPS port 443.

This traffic can blend with normal web traffic.

### DNS

Attackers may abuse DNS communication.

One technique is **DNS Tunneling**.

In simple words:

> **DNS Tunneling = Abuse DNS traffic as a communication channel.**

The infected computer may send specially constructed DNS requests to attacker-controlled infrastructure.

# 7. Actions on Objectives

This is the final stage.

The attacker performs actions to achieve the original goal.

Simply remember:

> **Actions on Objectives = Attacker achieves the mission.**

Possible objectives include:

* Credential collection.
* Privilege escalation.
* Internal reconnaissance.
* Lateral movement.
* Data collection.
* Data exfiltration.
* Backup deletion.
* Data corruption.

### Privilege Escalation

**Privilege Escalation** means gaining higher permissions.

Example:

**Normal User → Administrator → Domain Administrator**

### Internal Reconnaissance

After entering the network, the attacker explores internal systems.

They may identify:

* Servers.
* Applications.
* Users.
* Network resources.

### Lateral Movement

**Lateral Movement** means moving from one compromised system to another.

Example:

**Employee PC → Internal Server → Domain Environment**

### Data Exfiltration

**Data Exfiltration** means unauthorized transfer of data out of the organization.

Example:

**Company Data → Attacker-Controlled Destination**

### Delete Backups and Shadow Copies

Attackers, especially ransomware operators, may attempt to damage recovery capabilities.

**Shadow Copy** is a [Microsoft](https://www.microsoft.com/?utm_source=chatgpt.com) Windows technology used to create point-in-time copies or snapshots of files and volumes.

Deleting recovery data can make system restoration more difficult.

For the TryHackMe practical, map the six provided items like this:

| ----------------------------------- | -------------------------------- |
| `spearphishing attachment`          | Delivery                         |
| `exploit public-facing application` | Exploitation                     |
| `powershell`                        | Execution / Exploitation context |
| `dynamic linker hijacking`          | Installation / Persistence       |
| `fallback channels`                 | Command & Control                |
| `data from local system`            | Actions on Objectives            |

One important point: the listed items are ATT&CK-style technique names, so mapping them into the older Cyber Kill Chain can sometimes depend on the scenario presented by the lab.

# Advantages of the Cyber Kill Chain

The Cyber Kill Chain helps defenders:

* Understand the stages of an attack.
* Recognize intrusion attempts.
* Understand attacker objectives.
* Find missing security controls.
* Identify security gaps.
* Break attacks before the final objective.

For example:

**Phishing Detected at Delivery → Email Blocked → Later Attack Stages Never Occur**

This is called:

> **Breaking the Kill Chain**


# Limitations of the Traditional Cyber Kill Chain

The traditional Cyber Kill Chain is useful, but it is **not perfect**.

It was introduced in 2011 and is strongly focused on perimeter-oriented intrusion and malware-delivery scenarios.

Modern attackers may combine many TTPs and may not always follow a simple linear attack path.

Another limitation is **Insider Threats**.

An insider may already have authorized access.

Therefore, stages such as external delivery or initial exploitation may not happen in the same way.

The Cybersecurity and Infrastructure Security Agency defines insider threat around the potential for insiders to use authorized access or knowledge to harm an organization.

Because of these limitations, defenders often combine the Cyber Kill Chain with the [MITRE ATT&CK knowledge base](https://attack.mitre.org/?utm_source=chatgpt.com) and other models such as the [Unified Kill Chain](https://www.unifiedkillchain.com/?utm_source=chatgpt.com).

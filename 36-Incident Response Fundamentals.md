# Introduction to Incident Response

Organizations use many security measures such as:

* Firewalls
* Antivirus
* SIEM
* EDR
* IDS/IPS

These help **prevent cyber attacks**, but **no security is 100% perfect**.

Attackers may still bypass these defenses and compromise systems.

When this happens, the organization must know **how to detect, contain, investigate, and recover from the attack**.

This process is called **Incident Response (IR).**


# What is Incident Response?

**Incident Response (IR)** is the process of preparing for, detecting, responding to, and recovering from cybersecurity incidents.

Its main goal is to:

* Detect attacks quickly.
* Minimize damage.
* Recover systems.
* Prevent similar incidents in the future.


# Why is Incident Response Important?

Even with strong security controls, attacks can still happen.

Without an Incident Response plan:

* Attacks may spread.
* More systems may become infected.
* Sensitive data may be stolen.
* Recovery may take much longer.

A good Incident Response process reduces the impact of cyber attacks.


# Example

Imagine a company is infected with ransomware.

Without Incident Response:

* The malware spreads across the network.
* Files become encrypted.
* Business operations stop.

With Incident Response:

* The infected systems are isolated.
* The malware is removed.
* Data is restored from backups.
* The attack is investigated to prevent future incidents.


# What is a Security Incident?

A **Security Incident** is any event that threatens the **Confidentiality, Integrity, or Availability (CIA)** of an organization's systems or data.

Examples include:

* Malware infection
* Ransomware attack
* Data breach
* Phishing attack
* Unauthorized access
* Denial-of-Service (DoS) attack
------------

# Events, Logs, Alerts, and Incidents

Every action performed on a computer, laptop, server, or mobile device creates an **event**.

These events help security teams understand what is happening on a system.


# What is an Event?

An **Event** is any activity that occurs on a device or application.

Events can be generated by:

* Users
* Applications
* Operating System
* Background services


## Examples of Events

* User logs in.
* User logs out.
* File is created.
* File is deleted.
* Program starts.
* USB device is connected.
* Browser is opened.

Every one of these actions is considered an **event**.

# Interactive vs Non-Interactive Processes

Processes running on a system are generally of two types.

### Interactive Processes

These require user interaction.

Examples:

* Playing a game.
* Watching a video.
* Opening Microsoft Word.
* Browsing the Internet.


### Non-Interactive Processes

These run automatically in the background.

Examples:

* Windows Update
* Antivirus scanning
* Backup service
* System services

Although users don't interact with them, they still generate events.



# What is a Log?

A **Log** is a recorded event.

When an event occurs, the operating system or application stores it in a log file.

Think of a log as a **history record** of everything that happened on a system.


# Why Are Logs Important?

A single computer can generate **thousands or even millions of logs every day**.

Logs help investigators:

* Detect attacks.
* Investigate incidents.
* Troubleshoot problems.
* Monitor system activity.

# Security Solutions

Manually reviewing millions of logs is impossible.

Security tools automatically collect and analyze logs.

Examples include:

* SIEM
* EDR
* XDR

These tools look for suspicious patterns in the logs.


# What is an Alert?

An **Alert** is a notification generated by a security tool when it detects suspicious activity.

The alert tells the security team:

> "Something unusual happened. Please investigate."

An alert **does not always mean an attack has occurred**.

# False Positive

A **False Positive** is an alert that looks suspicious but is actually harmless.

After investigation, the activity is found to be legitimate.


## Example

A SIEM generates an alert because a large amount of data is being transferred.

After investigation, analysts discover:

* The company is performing a scheduled cloud backup.

The activity is legitimate.

**Result:** False Positive


# True Positive

A **True Positive** is an alert that correctly identifies a real security threat.

After investigation, the activity is confirmed to be malicious.


## Example

The SIEM detects a phishing email.

Investigation confirms:

* The email is malicious.
* It contains a fake login page.

**Result:** True Positive

# Incident

Once an alert is confirmed to be a **True Positive**, it becomes a **Security Incident**.

An **Incident** is a confirmed security event that requires response.
 

# Incident Severity

Organizations may experience multiple incidents at the same time.

Since security teams cannot respond to all incidents simultaneously, each incident is assigned a **severity level**.

Severity helps determine which incident should be handled first.

 

# Severity Levels

## Low

Small impact on the organization.

Example:

* Antivirus detects a harmless test file.

 

## Medium

Moderate impact.

May require investigation but is not immediately dangerous.

Example:

* Multiple failed login attempts.

 

## High

Serious incident requiring immediate attention.

Example:

* Malware infection on an employee's computer.

 

## Critical

The highest priority.

Can significantly impact the organization.

Examples:

* Ransomware attack
* Domain Controller compromise
* Large-scale data breach

Critical incidents are handled first.

# Common Types of Security Incidents

Not every cyber attack is simply called **"hacking."**

In cybersecurity, security incidents are classified into different types based on **how the attack happens** and **what its goal is**.

An organization may experience one or multiple types of incidents at the same time.

# 1. Malware Infection

**Malware** is malicious software designed to damage, disrupt, or gain unauthorized access to a system.

It is one of the most common security incidents.

### Common Types of Malware

* Virus
* Worm
* Trojan
* Ransomware
* Spyware
* Rootkit

### How Malware Spreads

* Malicious email attachments
* Fake software downloads
* Infected USB drives
* Malicious websites

### Example

A user downloads a fake PDF attachment from a phishing email.

The file installs ransomware and encrypts all company files.

# 2. Security Breach

A **Security Breach** occurs when an **unauthorized person gains access to confidential systems or data**.

The attacker successfully bypasses security controls.

### Examples

* Hacker logs into an employee account.
* Attacker gains access to a company database.
* Unauthorized access to confidential documents.

> **Goal:** Gain unauthorized access.


# 3. Data Leak

A **Data Leak** occurs when confidential information is **exposed or disclosed to unauthorized people**.

Unlike a Security Breach, a Data Leak **does not always involve an attacker**.

It may happen accidentally.

### Causes

* Human error
* Misconfigured cloud storage
* Sending confidential files to the wrong person
* Attacker publishing stolen data

### Example

An employee accidentally uploads customer records to a public cloud folder.



# Security Breach vs Data Leak

| Security Breach              | Data Leak                                     |
| ---------------------------- | --------------------------------------------- |
| Unauthorized access to data. | Confidential data becomes exposed.            |
| Usually caused by attackers. | Can be caused by attackers or human mistakes. |


# 4. Insider Attack

An **Insider Attack** is performed by **someone inside the organization**.

The attacker already has legitimate access to company resources.

### Examples

* Employee steals confidential data.
* Disgruntled employee installs malware.
* Administrator abuses privileged access.

Because insiders already have access, these attacks can be difficult to detect.


# 5. Denial of Service (DoS) Attack

A **Denial of Service (DoS)** attack attempts to make a system or service **unavailable** to legitimate users.

The attacker floods the target with excessive requests until it can no longer respond.

### Target

* Website
* Server
* Application
* Network

### Example

A website normally receives **500 requests per minute**.

An attacker sends **500,000 fake requests per minute**.

The server becomes overloaded and stops responding to real users.


# What Does DoS Affect?

A DoS attack mainly targets the **Availability** part of the **CIA Triad**.

The **CIA Triad** consists of:

* **Confidentiality** → Protect data from unauthorized access.
* **Integrity** → Ensure data is not modified improperly.
* **Availability** → Ensure systems and data remain accessible.

A successful DoS attack reduces **Availability**.


# Can Multiple Incidents Occur Together?

Yes.

One attack may involve multiple incident types.

### Example

```text
Phishing Email
      │
      ▼
Malware Installed
      │
      ▼
Security Breach
      │
      ▼
Sensitive Data Stolen
      │
      ▼
Data Leak
```

A single attack can result in:

* Malware Infection
* Security Breach
* Data Leak

 

# Does Every Incident Have the Same Severity?

No.

The severity depends on the organization.

### Example

Company A

* Online shopping website.
* A DoS attack stops customers from placing orders.
* Huge financial loss.

**Severity:** Critical

 

Company B

* Internal training website.
* Temporary downtime has little business impact.

**Severity:** Low or Medium

The same type of incident can have different impacts depending on the organization's business.
